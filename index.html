Algorithms and representations

An algorithm is a finite, ordered and unambiguous sequence of steps that transforms input into the required output. A good algorithm terminates, is correct for all valid cases, states each step precisely, uses executable operations, and is general enough for the stated problem rather than one example.

PseudocodeLanguage-independent structured text. Use assignment, selection, iteration, procedure/function calls, clear parameters and an explicit returned value where required.
FlowchartOval: start/end. Rectangle: process or assignment. Parallelogram: input/output. Diamond: decision. Arrow: direction of control. Connector: joins separated parts.
DecompositionBreak a complex problem into smaller sub-problems that can be designed, tested and reasoned about separately.
Modular designBuild independent, cohesive modules with clear interfaces. This improves reuse, testing, maintenance and team development.
Flowchart and trace: preserve the order of operations

A-level 2024 Q1(a–c) · Answer-key / examiner-commentary synthesis

Use a terminator for start/end, a parallelogram for input/output, a rectangle for assignments and a diamond for a Boolean decision. Label decision branches and draw the loop-back arrow explicitly.

Required control flow: initialise c=0 → input i → test i≠−1 → if true, input n → test n>i and increment c only on the true branch → one process box labelled SWAP(n,i) → loop to the i≠−1 test. When the test is false, output c and stop. The question explicitly requires SWAP as a single process.

For HELLO followed by the sentinel, comparisons are 69>72 (false), 76>69 (true), 76>76 (false), 79>76 (true), −1>79 (false). The final output is 2. The algorithm counts adjacent increases in character-code order, not the largest code or the number of distinct letters.

The sentinel is read inside the loop before being moved into i. Do not move the stop test or the swap to a different point and then trace your changed algorithm.

Decision tables

A decision table lists conditions above actions. With n independent Boolean conditions, begin with 2ⁿ rules. Fill every True/False combination, assign exactly the intended action(s), then merge rules only when a changed condition does not affect the outcome. Mark that proven irrelevant condition with a dash.

conditions → enumerate every combination → assign actions → prove redundancy → replace irrelevant entries with “–” → translate into mutually exclusive selection

When translating to code, order branches so that a broader condition cannot capture input meant for a narrower one. Trace boundary values and ensure every valid combination reaches exactly one outcome.

Searching

Linear search, O(n)Inspect elements from the beginning until the key is found or all elements are exhausted. It works on unsorted data. Worst case: the item is last or absent, so all n items are examined.
Binary search, O(log n)Requires sorted data. Compare the middle item, discard the impossible half, and repeat while low ≤ high. Return not-found only after the bounds cross.
  1. Set low to the first index and high to the last.
  2. Compute mid = (low + high) DIV 2.
  3. If equal, return mid; if the key is larger, use low = mid + 1; otherwise use high = mid - 1.

Hashing and collisions

A hash function maps a key to a table index. A common exam function is index = key MOD tableSize. With no collision, insert at that index. A collision occurs when different keys map to the same index.

Separate chainingEach table slot refers to a bucket or linked list. Hash the key, go to that bucket, then search within it. Colliding items share the bucket.
Linear probingTry (hashIndex + i) MOD tableSize for i = 0,1,2,… until an unused slot appears. The modulo wraps the probe to the start.

For a successful probe search, continue through occupied non-matches until the key is found. For an unsuccessful search, stop at the first slot that has never been used. A deleted-slot marker must not be treated as never-used, or a key farther along the collision cluster may be missed. Hash lookup is often O(1) average but can degrade to O(n) in the worst case.

Two distinct keys produce the same table index. With chaining, store both in the bucket/list at that index and search that chain. With probing, examine successive candidate slots, wrapping with modulo.
Three features
Same key always gives the same index; distribute keys approximately evenly to reduce collisions; calculate the index quickly. The result must lie within the table's valid index range.
Do not write
“No collisions ever”, “always O(1)” or cryptographic properties such as one-way hashing as the main justification for a storage-index hash.

Static array versus dynamically allocated linked list

A-level 2022 Q4(a–b); 2023 Q2(a), Q4(a); 2024 Q5(b) · Answer-key / examiner-commentary synthesis

  • Array advantage: direct indexed access; a sorted array supports efficient binary search. It does not need one next-pointer per item.
  • Linked-list advantage: allocate nodes as needed when the final size is unknown; insert/delete by relinking nodes without shifting all later data. Finding the position may still take O(n).
  • Static limitation: fixed capacity can fill up, or reserve unused slots. “Fixed capacity” does not mean every array in every language is allocated at compile time.
  • Dynamic limitation: pointers and allocation management add overhead; allocation can fail; poor manual deallocation can leak memory. Total memory is not automatically smaller than an array.
  • Implementation matters: a linked list can be stored in a fixed array of records with integer indices as pointers. The abstract data type alone does not determine static/dynamic allocation.

Pointer updates: reason from the invariant

Implementation teaching example, synthesising A-level structure questions and retained prelim patterns

An invariant is a fact that must still hold after an operation: Head reaches the first live node, every live node is reachable exactly once, and the last link is null. In a static implementation, allocated nodes and free nodes must not overlap.

  1. Allocate: if Free = −1, report full. Otherwise save New = Free, then advance Free to the old next link of New. Only now overwrite New.
  2. Insert at head: set Node[New].next = Head, then Head = New. This also handles an empty list.
  3. Insert after Previous: set Node[New].next = Node[Previous].next, then Node[Previous].next = New. Reversing these assignments can lose the suffix.
  4. Delete: save Removed and its successor. If deleting the head, update Head; otherwise redirect the predecessor to the successor. Update Tail too if the implementation stores one and the last node was removed.
  5. Return a static node to the free list: Node[Removed].next = Free; Free = Removed. A dynamically allocated implementation instead releases the node appropriately.

Worked change: Head=2 and chain 2→5→8→−1. Insert node 6 after node 5: set next[6]=8, then next[5]=6. The result is 2→5→6→8→−1. Delete node 5: next[2]=6; return node 5 to free storage. Array position is not list order.

Circular queue: one consistent convention

Implementation teaching example supporting A-level 2020 Q3(h), 2023 Q4(d)

Choose Front as the next item to remove, Rear as the next free insertion position, and Count as the number of stored items. Initially all three are 0. Capacity is N.

ENQUEUE(value):
    IF Count = N: report full; stop
    Q[Rear] = value
    Rear = (Rear + 1) MOD N
    Count = Count + 1

DEQUEUE():
    IF Count = 0: report empty; stop
    value = Q[Front]
    Front = (Front + 1) MOD N
    Count = Count - 1
    RETURN value

With capacity 4, enqueue A,B,C; dequeue A,B; enqueue D,E. The live order is C,D,E even though E occupies array index 0. Front=2, Rear=1, Count=3. No live items need to be shifted. If the paper defines Rear as the last occupied slot instead, adapt the update order to that definition.

Choose and trace a sort without overgeneralising

New PDF pp. 5–8; syllabus 1.2.1–1.2.5

  • Stability: equal-key records keep their original relative order. Bubble/insertion are stable when they do not swap/shift equal keys; merge is stable when ties are taken from the left half first. Ordinary in-place quicksort is generally not stable.
  • Already/nearly sorted: insertion needs few shifts; bubble reaches O(n) only with an early-stop test. An unoptimised bubble sort can still make O(n²) comparisons on sorted input.
  • Guaranteed worst-case bound: ordinary merge sort gives O(n log n); quicksort can give O(n²) after repeatedly unbalanced partitions. “Large array” alone does not prove quicksort is always better.
  • Linked-list sorting: merge sort can merge by relinking sequentially accessible nodes; binary search and array-style partitioning assume access patterns a linked list does not provide efficiently.
  • Extra context, not required space-complexity analysis: array merge usually needs a temporary buffer; recursive quicksort still uses call-stack space. External merge sorts chunks on secondary storage; it is enrichment, not an additional named 2026 syllabus sort.

Duplicates: partition rules must retain every equal value and shrink the recursive problem. Do not place the pivot back into a recursive range that includes itself indefinitely.

Four complete sorting implementations

Syllabus 1.2.1, 2.3.1; implementations independently written and tested

All functions below mutate the supplied list and return it. Trace every swap/shift under the shown convention; other correct pivot conventions can produce different intermediate arrays. The merge code explicitly chooses the left item on ties.

def bubble_sort(a):
    end = len(a) - 1
    while end > 0:
        swapped = False
        for i in range(end):
            if a[i] > a[i + 1]:
                a[i], a[i + 1] = a[i + 1], a[i]
                swapped = True
        if not swapped:
            break
        end -= 1
    return a

def insertion_sort(a):
    for i in range(1, len(a)):
        key = a[i]
        j = i - 1
        while j >= 0 and a[j] > key:
            a[j + 1] = a[j]
            j -= 1
        a[j + 1] = key
    return a

def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    i = j = k = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            a[k] = left[i]
            i += 1
        else:
            a[k] = right[j]
            j += 1
        k += 1
    a[k:] = left[i:] + right[j:]
    return a

def quick_sort(a):
    def sort_range(low, high):
        if low >= high:
            return
        pivot = a[high]
        split = low
        for j in range(low, high):
            if a[j] <= pivot:
                a[split], a[j] = a[j], a[split]
                split += 1
        a[split], a[high] = a[high], a[split]
        sort_range(low, split - 1)
        sort_range(split + 1, high)
    sort_range(0, len(a) - 1)
    return a

Create, insert and remove: stack and linear queue

The stack uses Top as the last occupied index. This non-compacting linear queue uses Front as the next removal index and Rear as the next insertion index. It resets when empty; while nonempty, freed front slots are not reused. Compare this with the circular-queue implementation already given.

class FixedStack:
    def __init__(self, capacity):
        self.data = [None] * capacity
        self.top = -1

    def push(self, value):
        if self.top == len(self.data) - 1:
            return False
        self.top += 1
        self.data[self.top] = value
        return True

    def pop(self):
        if self.top == -1:
            raise IndexError("empty stack")
        value = self.data[self.top]
        self.data[self.top] = None
        self.top -= 1
        return value

class LinearQueue:
    def __init__(self, capacity):
        self.data = [None] * capacity
        self.front = self.rear = 0

    def enqueue(self, value):
        if self.rear == len(self.data):
            return False
        self.data[self.rear] = value
        self.rear += 1
        return True

    def dequeue(self):
        if self.front == self.rear:
            raise IndexError("empty queue")
        value = self.data[self.front]
        self.data[self.front] = None
        self.front += 1
        if self.front == self.rear:
            self.front = self.rear = 0
        return value

Recursion: calls go down, results come back up

Additional V8 theory PDF, pp. 23–25 · Corrected teaching notes and worked examples; not an official marking scheme.

def factorial(n):
    # Precondition: n is a non-negative integer.
    if n <= 1:
        return 1
    return n * factorial(n - 1)

Explain each mark-bearing part: n ≤ 1 is the base case; factorial(n − 1) is the recursive call; decrementing n moves valid input towards the base case. The caller waits for a value before multiplying. Each call has its own local n and return location in a stack frame.

For factorial(4), four factorial frames are active at the deepest point (not counting the surrounding caller). The suspended callers’ values are retained, not overwritten by the callee. Recursion can express a recursive structure clearly, but adds calls/frames and may exceed the recursion limit. A reachable base case prevents unbounded recursion; it does not make arbitrarily deep inputs safe.

Hash collisions: worked probing and load-factor example

Additional V8 theory PDF, pp. 12–14, 21 · Corrected teaching notes and worked examples; not an official marking scheme.

Linear probing: with seven slots indexed 0–6 and h(k) = k MOD 7, insert 10 at 3, 17 at 4 after collision at 3, and 24 at 5 after collisions at 3 and 4. Searching for 24 must compare keys at 3, 4 and 5. A matching hash index is not necessarily a matching key.

Load factor: stored entries ÷ number of buckets/slots. Here it is 3/7. Higher occupancy usually increases collisions/probe work. Open addressing keeps entries in the table and needs a free slot for insertion; separate chaining stores colliding entries in the same bucket’s collection and can have more entries than buckets.

Quadratic probing (supporting variant): a specified sequence may use (h(k) + i²) MOD m for i = 0, 1, 2, … . For h = 3 and m = 7, the first positions are 3, 4, 0, 5. Such a sequence need not visit every slot; use the question’s exact rule and termination bound. Do not replace a requested linear probe with this variant.

Deletion: in open addressing, clearing a slot to the ordinary “never used” marker can break a later key’s search path. Use the specified deleted marker (tombstone) or an appropriate reorganisation, and continue past deleted slots during search. Separate chaining removes the entry from its bucket.

Good storage hash: deterministic for a key, quick to calculate, produces valid indices and spreads typical keys across the table. Cryptographic one-way/collision-resistance properties are not necessary for a storage-index hash. A larger table may reduce load but does not guarantee no collisions.

Memory leak: explain the whole failure chain

A-level 2022 Q5 · Answer-key / examiner-commentary synthesis

  1. Every button press allocates memory for a floor number.
  2. If the lift is already at that floor, the early exit skips the release step.
  3. Repeated presses therefore leave allocated memory unreleased; available memory is gradually exhausted and the system fails.
  4. Release memory on both branches, or allocate only when needed; ensure all exits clean up.
  5. Tests may omit same-floor presses or run for too short a time for the small repeated leak to exhaust memory. Restarting clears the accumulated state, but does not fix the algorithm.

Serial/sequential files: read, process, write

Syllabus 2.3.4; independently written teaching example

Serial records are commonly described as stored in arrival order; sequential files are organised in a chosen key order. Both can be processed one record after another. A sequential scan does not imply direct random access to a record.

This example reads name/score rows, validates scores, sorts by name and writes a new text file. Assume names contain no commas; use the csv module for general CSV with quoted commas. Write mode truncates an existing output file. Do not use the source filename as the destination when it must be preserved.

def process_scores(source, destination):
    records = []
    with open(source, "r", encoding="utf-8") as f:
        for line_no, line in enumerate(f, 1):
            if not line.strip():
                continue
            parts = line.rstrip("\n").split(",")
            if len(parts) != 2:
                raise ValueError(f"Invalid row {line_no}")
            name, text_score = parts
            score = int(text_score)
            if not name.strip() or not 0 <= score <= 100:
                raise ValueError(f"Invalid data at row {line_no}")
            records.append((name, score))
    records.sort(key=lambda item: item[0])
    with open(destination, "w", encoding="utf-8") as f:
        for name, score in records:
            f.write(f"{name},{score}\n")
    return records

NoSQL and MongoDB

Relational SQL systems use structured tables, keys, constraints and joins. NoSQL is a family of non-relational models. MongoDB is a document database: database → collection → BSON document → fields/key-value pairs. Every document has a unique _id; a field may contain an array or embedded document, such as an address with street, city and postal code.

NoSQL strengthsFlexible schema for changing/semi-structured data; horizontal scaling across servers; high throughput for suitable access patterns; natural storage of nested data and very large volumes.
NoSQL trade-offsLess standardised across products; duplication may increase; complex relationships/joins may be awkward; some designs trade immediate consistency for availability or scale.

Choose SQL when strong relationships, referential integrity, transactions and complex joins dominate. Choose a document model when records vary, nested data is natural and the system must distribute a large workload. A complete normalisation walkthrough

Independently worked teaching version of A-level 2021 Q2; no 2021 key supplied

Suppose a project-work row contains ProjectID, ProjectTitle, EmployeeID, EmployeeName, SkillID, SkillName, CostPerHour and HoursWorked. Assume one total hours figure per employee/project, and one skill per employee as stated.

SQL clauses: how to assemble and check an answer

Expanded implementation guidance supporting the A-level SQL questions

  • SELECT: list only the required output attributes, qualifying identical names with aliases.
  • JOIN … ON: connect matching PK/FK values. Without the relationship condition, unrelated rows can multiply into a Cartesian product.
  • WHERE: filter individual rows; quote text values and compare numbers numerically.
  • GROUP BY: collect rows per requested category; COUNT counts rows/non-null expressions, SUM adds values, AVG averages.
  • HAVING: filter aggregate groups. An aggregate condition such as COUNT(*) > 2 belongs here, not in WHERE.
  • ORDER BY: use DESC for highest-first; without ordering, the result order is not guaranteed.

Foreign-key effect: referential integrity prevents a child key from referring to a missing parent when enforced; it does not guarantee that every parent has a child. Uniqueness and NOT NULL are separate constraints.

SQL safety: pass external values as parameters. Constructing SQL by concatenating user input lets input become query syntax. Parameterisation keeps those values as data.

Devices and network scope

A node is an addressable device or connection point on a network. A host is an endpoint that provides or consumes services, such as a client or server. All hosts are nodes, while infrastructure such as a switch can be a node without being an application host. A NIC provides the wired or wireless interface and has a link-layer address; examples include Ethernet and Wi-Fi interfaces.

Hub, switch and router

  • Hub: repeats an incoming signal to all other ports. Devices share bandwidth and a collision domain; traffic exposure makes it inefficient and insecure.
  • Switch (Layer 2): connects a LAN and forwards Ethernet frames using destination MAC addresses. It learns a source-address table (SAT/MAC table) by recording each incoming frame’s source MAC and port. An unknown destination is flooded to all other relevant ports; after replies are learned, unicast traffic goes only to the matching port. A basic switch remains one broadcast domain.
  • Router (Layer 3): connects different IP networks. It reads the destination IP/network, consults a routing table and forwards to a next hop. A device sends off-network traffic to its default gateway. Each router interface belongs to the network it connects.
Why can’t a switch alone connect different network IDs? A switch makes local forwarding decisions using MAC addresses; a router understands IP network prefixes and can select a path between separate networks.

MAC, IP, subnet masks and ARP

A MAC address is usually a 48-bit hexadecimal identifier for a network interface on a local link. Manufacturers assign globally administered addresses, but software can use locally administered, randomised or spoofed values, so “permanently burned in and unchangeable” is unsafe wording. Routers do not forward the original Ethernet frame end-to-end: at each link, a new frame uses appropriate next-hop source/destination MAC addresses while the packet’s end-to-end IP addresses normally remain.

IPv4 uses 32 bits in dotted decimal. Private addresses are used internally and are not globally routed; a public address is globally routable. NAT lets a gateway translate internal private source addresses/ports to public mappings. A subnet mask has 1-bits for the network prefix and 0-bits for the host portion; 255.255.255.0 is /24. Calculate IP AND mask to obtain the Network ID. Matching IDs mean direct local delivery; otherwise send to the gateway.

ARP resolves a known IPv4 address to the appropriate MAC address on the local network. For a remote destination, the sender resolves the default gateway’s MAC, not the remote server’s MAC.

Example: 192.168.0.10/24 and 192.168.1.20/24 have Network IDs 192.168.0.0 and 192.168.1.0. They differ, so the first host frames the packet to its router’s MAC; routers forward it to the destination network.

Topologies and switching

Physical topology is the cabling/layout; logical topology is the route signals/data take; a hybrid combines designs. Point-to-point joins two nodes; point-to-multipoint joins one central node to several others. A bus shares one backbone and is cheap but failure/collisions hurt the whole network. A ring forms a loop and a break can disrupt it without redundancy. A star connects every endpoint to a central switch; one cable failure is isolated, but the switch is a single point of failure. A mesh adds redundant paths; full mesh is fault tolerant but expensive. Full-mesh links: n(n−1)/2, so six devices need 15 links.

Circuit switchingreserves one dedicated channel for the session, giving predictable service but wasting idle capacity. Packet switchingsplits data into addressed packets that share links, may take different routes and are reassembled at the destination. It is efficient and resilient, so the Internet uses it; VoIP carries voice over packet-switched networks.

Packet switching and routing: a causal sequence

A-level 2020 Q4(a–c); 2022 Q7; 2023 Q5(b) · Answer-key / examiner-commentary synthesis

  1. Split the message into packets so traffic can share network links; in a reliable transfer protocol, lost/corrupted portions can be retransmitted without resending the whole message.
  2. Packets carry addressing information; source IP and destination IP are two distinct header items. Sequence numbering lets the receiving transport/application reassemble data in order.
  3. Routers inspect destination IP addresses and use routing tables to choose a next hop/interface toward the destination.
  4. Packets may follow different routes and arrive out of order. Routers can use an available alternative route around a failed link; packets do not decide their own routes.
  5. The receiver reorders/reassembles the data. Delivery/retransmission guarantees depend on the protocols used; IP alone does not guarantee arrival.

Protocol: an agreed set of communication rules followed by both ends, defining formats and interpretation/handling of messages so different devices interoperate. Say “source IP” and “destination IP”, not “the IP”. Port numbers identify transport endpoints/services, not IP routing destinations.

DNS (2020): return the host's IP address from a cache or queries to other DNS servers; cache a newly obtained answer. DNS does not retrieve the web page.

Servers, Internet and application services

A server is a computer or program that provides a service to clients. Organisational servers emphasise continuous operation and concurrent load, using server-class CPUs, large ECC memory, RAID/hot-swappable storage, redundant power and server operating systems where appropriate. These improve reliability but are design choices, not a requirement for software to be a server.

The Internet is a global network of networks connected through ISPs and routers over fibre, copper, wireless and satellite links. The Web is one service on top of it, consisting of linked resources transferred mainly via HTTP/HTTPS. Not every server has its own unique public IP: virtual hosting, reverse proxies, CDNs and NAT can let services share or hide addresses.

  • DNS: resolves a domain to records. A client/cache asks a recursive resolver; on a cache miss it follows root → TLD → authoritative servers, caches the answer for its TTL and returns it. MX records identify mail exchangers.
  • DHCP: leases IP configuration from a scope, commonly including address, mask, gateway and DNS server. Automation saves work and reduces duplicate/mistyped configuration.
  • SMTP: sends mail from client to outgoing server and between mail servers, using reliable TCP.
  • POP3: retrieves mail to a client. Deletion is controlled by client/server policy; it is often configured for download-and-delete but the protocol does not require every retrieval to erase mail.
  • IMAP: keeps server mailboxes and state synchronised across devices. Webmail manages server-held mail through a browser.

Follow a request to a remote website

Integrated explanation based on the supplied network notes and A-level DNS/routing questions

  1. Resolve the URL’s hostname using DNS unless a usable cached answer already exists.
  2. The client compares the destination network with its own network using its configured mask/prefix. If remote, send via the default gateway.
  3. On an Ethernet IPv4 LAN, obtain the gateway’s MAC address using ARP if it is not cached; create a local frame addressed to that MAC.
  4. The switch forwards the frame locally. The router removes that link-layer frame, examines the destination IP and forwards over the next link in a new frame.
  5. The destination transport port directs the request to the appropriate service. The application responds; browser code renders the returned content.

Do not mix jobs: DNS resolves names; DHCP supplies IP configuration; ARP resolves a local next-hop IPv4 address to a MAC address; NAT translates addresses/ports at a gateway; routing selects how to reach another IP network.

Failure explanation: an unavailable DNS answer can prevent access by hostname even if the server is running. A broken route can prevent packet delivery even with a correct DNS answer. State which step fails rather than saying “the internet is broken”.

Iterative TCP server and matching client

Syllabus 4.1.6; independently written protocol example

Server order: socket → bind → listen → accept → receive/process/send → close accepted socket → accept the next client. The listening socket is distinct from each connected socket. An iterative server handles one client at a time; a slow client can delay the next.

This protocol uses UTF-8 and one newline-terminated request/response per connection. Both ends must agree on framing and order. TCP is a byte stream: a single recv is not guaranteed to return an entire application message. A buffered readline handles fragmentation here; an empty read indicates closure. sendall attempts to send all supplied bytes or raises an error.

Run the server in one process, then call the client in another. The localhost address keeps this teaching service on the same computer. The max_clients option allows a finite test run; the normal default keeps serving.

import socket

def handle_client(conn):
    with conn.makefile("rb") as incoming:
        request = incoming.readline(4097)
        if len(request) > 4096 or not request.endswith(b"\n"):
            conn.sendall(b"ERROR invalid request\n")
            return
        try:
            text = request[:-1].decode("utf-8")
        except UnicodeDecodeError:
            conn.sendall(b"ERROR encoding\n")
            return
        conn.sendall((text.upper() + "\n").encode("utf-8"))

def serve(port=5050, max_clients=None):
    with socket.socket(socket.AF_INET, socket.SOCK_STREAM) as listener:
        listener.bind(("127.0.0.1", port))
        listener.listen()
        count = 0
        while max_clients is None or count < max_clients:
            conn, address = listener.accept()
            with conn:
                handle_client(conn)
            count += 1

def ask(text, port=5050):
    if "\n" in text:
        raise ValueError("one line only")
    with socket.create_connection(("127.0.0.1", port), timeout=5) as conn:
        conn.sendall((text + "\n").encode("utf-8"))
        with conn.makefile("rb") as incoming:
            reply = incoming.readline()
        if not reply.endswith(b"\n"):
            raise ConnectionError("incomplete response")
        return reply[:-1].decode("utf-8")

DNS and routing: separate names, addresses and next hops

DNS answer: extract the host name from the URL; check available caches; a resolver obtains a record (typically A for IPv4 or AAAA for IPv6), returns the address and caches it for its time-to-live. The browser then contacts the server. DNS resolves names, not the complete URL path; it does not download the web page. Root/TLD replies are referrals, not HTTP redirects. DNS specification.

Local versus remote: with address 192.168.1.10 and mask 255.255.255.0, the network is 192.168.1.0/24. 192.168.1.1 can be the router’s local interface; it is not the network address. A remote destination is sent via the default gateway. The router selects a next hop/interface from its routing table; a LAN switch forwards an Ethernet frame using its destination MAC address.

Address traps: an IP address identifies an interface in context, not a permanent person. A MAC address can be changed/spoofed or randomised, so “permanently unique for each device” is too absolute. 0.0.0.0 used to bind a server means listen on available local IPv4 interfaces; it is not a remote server’s usable destination address.

Scope: an intranet is an organisation’s private network/services using Internet technologies; it need not be confined to one LAN. An extranet gives authorised outsiders limited access. Internet is the network of networks; the Web is one service using it.

Why layers? defined interfaces divide a complex task into modules; a layer can change while preserving its interface, supporting interoperability, maintenance and fault isolation. Layers cooperate—“independent” does not mean they communicate without one another.

Packet switching: links are shared by packets from different senders, avoiding reservation of an idle end-to-end circuit. Architecture comparison: a single unreplicated server is a potential point of failure, but replication can improve availability. Preventive and detective controls

A firewall permits or denies incoming/outgoing traffic according to rules. Stateless filteringjudges individual packets using fields such as source/destination IP, port, protocol or direction. MAC filtering is local-link access control rather than an Internet-wide identity check. Stateful filteringtracks connection state and judges packets in the context of an established flow. Content/application filtering examines higher-level information when the firewall supports it.

An IDSdetects suspicious activity, logs it and alerts administrators. An IPSsits in a position to block, drop, quarantine or reset malicious traffic as well as record/report it. Neither is perfect: signatures can miss new attacks, anomaly rules can produce false positives, and encrypted traffic limits inspection unless decrypted lawfully at a trusted point.

Firewall, IDS, denial of service and authentication

Firewall
Compare traffic with configured rules, such as allowed source/destination addresses, ports and protocols; allow permitted traffic and drop/reject prohibited traffic. Monitoring alone is not filtering.
IDS
Monitor traffic/events; analyse signatures or unusual behaviour for suspected intrusions; log and alert an administrator. These are three distinct functions. Automatic blocking is the defining role of an IPS, although products can combine functions.
DoS
Excess requests/traffic exhaust bandwidth or server resources so legitimate requests become slow or fail. A sudden legitimate audience surge can also trigger anomaly thresholds: an alert is not proof of an attack.
Authentication
Give a situation plus a method: a user signs in with credentials/MFA; a client checks a server certificate before trusting a service. Verifying identity differs from authorising what that identity may do.
Limits
Permitted traffic can still contain attacks; encrypted content may not be visible to a simple filter; detection can miss new attacks or raise false alarms. Match the limitation to the actual control.

Attacks and malware

  • Phishing: impersonation using deceptive messages, domains, links or forms to steal data or trigger action. Urgency, mismatched domains and requests for secrets are warning signs. Verify through a trusted channel; report and delete suspicious messages.
  • Virus: attaches to a host file/program and spreads when it executes or is shared. Worm: self-replicates across networks without a host file or normal user action.
  • Trojan: appears legitimate but installs malicious capability or steals data. Spyware: secretly monitors activity such as keystrokes. Ransomware: encrypts/locks data and demands payment.
  • DoS/DDoS: overwhelms availability with traffic or expensive requests. DDoS uses many distributed sources, often a malware-controlled botnet, making simple source blocking ineffective.

Reduce risk with patched systems, reputable updated anti-malware, least privilege, backups tested for restoration, network segmentation, rate limiting and user training. Connect each control to confidentiality, integrity or availability.

Encryption, signatures and certificates

Symmetric encryptionOne shared secret encrypts and decrypts. It is fast for bulk data, but the key must be exchanged securely. Caesar shift illustrates the idea but is trivially brute-forced; modern strength depends on algorithm and key size.
Asymmetric encryptionA mathematically linked public/private pair. For confidentiality, encrypt to the recipient’s public key and decrypt with their private key. It solves prior shared-secret distribution but is slower, so real protocols commonly combine it with symmetric session keys.

A digital signatureprovides origin authentication, integrity and non-repudiation evidence. The signer hashes the message and applies the signature algorithm with the private key. The verifier uses the public key and independently computed hash. Saying “the private key encrypts the whole message” is an exam simplification and is not a general description of modern signature schemes. To add confidentiality, encrypt the message/signature package for the recipient separately.

A digital certificatebinds an identity/domain to a public key. A trusted Certificate Authority signs certificate data, including subject, public key, issuer and validity period. A verifier checks the CA signature, hostname, dates, revocation/status and chain of trust. Certificates stop an attacker from simply substituting an unauthenticated public key; they do not make a compromised private key safe.

RSA is one example of public-key cryptography. Its key construction relies on properties of large prime numbers and the practical difficulty of factoring a sufficiently large product. Tiny or poorly generated keys are insecure. Public-key operations and longer keys are computationally expensive, which is why hybrid protocols use them to authenticate or establish a short-lived symmetric key rather than encrypting every byte asymmetrically.

Digital signature: memorise key ownership and verification order

A-level 2022 Q3(b); 2023 Q5(a); 2024 Q6(d–e) · Answer-key / examiner-commentary synthesis

  1. Create: sender hashes the message to create a digest.
  2. Sender signs that digest with the sender's private key; send message plus signature.
  3. Verify: receiver uses the sender's public key to verify the signature/authenticated digest.
  4. Receiver hashes the received message using the same hash algorithm.
  5. Compare digests: a match supports message integrity and origin authentication; a mismatch means verification fails, for example because the message was altered.

The supplied school answers describe signing/verifying as “encrypting/decrypting the digest”. Use that exam model when required, but keep the key owner correct. The public key must be reliably associated with the claimed sender.

Confidentiality is different: encrypt to the recipient using the recipient's public key; the recipient decrypts with the recipient's private key. A signature alone does not hide the message. An unprotected hash sent with a message can be replaced along with the message by an attacker.

Foundations

The Personal Data Protection Act governs private-sector organisations’ collection, use and disclosure of personal data while recognising reasonable business needs. Personal data is data, whether true or false, about an identifiable individual, either by itself or with other information the organisation has or is likely to access. Examples include names combined with identifiers, NRIC/passport numbers, contact details, images, recordings, biometrics, addresses, location and potentially IP addresses when they identify a person.

Legal frameworks and the policy vacuum

James Moor’s logical malleabilitydescribes computers’ ability to be shaped for many functions. New capabilities create a policy vacuumbecause conduct appears before suitable rules; law then catches up after harms and interests are identified.

Bits, bytes and number bases

A bit is one binary digit. A byte is exactly eight bits; 8 bits have 2⁸ = 256 patterns, 16 bits have 65,536 and 32 bits have 4,294,967,296. Word sizes such as 16/32/64 bits are not alternative definitions of a byte. Convert binary to denary using powers of two; group binary in fours for hexadecimal. One hexadecimal digit represents four bits.

Character sets and encodings

ASCIIis a 7-bit standard with 128 code values: 95 printable characters and 33 control codes. For example, decimal 65 is A, and Python’s ord('4') is 52. ASCII’s limited repertoire motivated a universal character set.

Unicodeassigns characters abstract code points such as U+0041 and U+20AC. A code point is not itself a byte sequence; UTF-8, UTF-16 and UTF-32 are encodings that map code points to code units. Unicode grew beyond the early 16-bit design: Version 15.0 encoded 149,186 characters across 161 scripts, not 304,115 characters. The current standard is newer, but exam questions test the model, not memorisation of release counts.

Binary, hexadecimal, ASCII and UTF-8

A-level 2023 Q5(c); 2024 Q1(d); also 2021 Q6 and 2025 Q2(f) · Answer-key / examiner-commentary synthesis

  • Hex to decimal: 4D = 4×16 + 13 = 77. Hex to binary: one hex digit per four bits, so 4D = 0100 1101.
  • 2024 conversion: 79 = 4×16 + 15 = 4F = 0100 1111. For repeated division, divide the previous quotient again: 79÷16 gives quotient 4 remainder 15; 4÷16 gives quotient 0 remainder 4. Read remainders backwards.
  • ASCII: standard ASCII uses 7 bits, representing 128 codes (0…127). “256 ASCII characters” confuses ASCII with an 8-bit extended code page.
  • Unicode: supports many scripts and symbols beyond ASCII, allowing multilingual data to be represented consistently across systems. The first 128 Unicode code points agree with ASCII.
  • UTF-8: encodes a Unicode scalar value using 1–4 bytes; ASCII-range values use one byte. Unicode is not universally “16 bits per character”. Unicode FAQ.

Number-base conversion: show enough working to check it

Expanded method supporting the A-level representation questions

Binary to decimal: 01001101₂ = 64 + 8 + 4 + 1 = 77. Zero positions contribute nothing. Hex to decimal: 4D₁₆ = 4×16 + 13 = 77.

Decimal to binary: repeatedly divide by 2, record remainders, read them from last to first. Decimal to hex: use division by 16 and replace remainders 10…15 with A…F. Divide the quotient at the next step.

Width: 1001111₂ and 01001111₂ have the same numeric value, 79; use the leading zero when eight bits are requested. An identifier such as 02757 is different: leading zeros are part of its textual representation and must not be discarded.

Character versus number: the character '4' has ASCII value 52; the integer 4 has numeric value 4. Converting a digit string to a number is different from asking for its character code.

Decode UTF-8 without counting prefix bits as data

Retained course-detail expansion; not claimed as a new A-level question

For C2 A3, binary bytes are 11000010 10100011. The first prefix 110 signals two bytes; the second starts with continuation prefix 10. Remove prefixes and join payloads: 00010 + 100011 = 00010100011 = 163 = U+00A3 (£).

Check that the required continuation bytes exist and begin with 10. Validity also requires legal scalar ranges and shortest-form encoding; surrogate code points U+D800…U+DFFF are excluded. One displayed symbol can comprise multiple Unicode code points, so byte count, code-point count and visible-character count are not universally equal.

Convert between bases programmatically

Syllabus 3.1.2 and 3.2.2; fills a code-level coverage gap

These functions accept bases 2…16 and non-negative integers; the syllabus specifically requires positive-integer conversions for binary/decimal/hex. Zero handling is included as a useful edge case. To convert base 2 to base 16, first parse the input, then format the numeric result. For example, 1101101₂ → 109 → 6D₁₆.

DIGITS = "0123456789ABCDEF"

def to_base(n, base):
    if not 2 <= base <= 16 or n < 0:
        raise ValueError("invalid base/value")
    if n == 0:
        return "0"
    result = ""
    while n > 0:
        result = DIGITS[n % base] + result
        n //= base
    return result

def from_base(text, base):
    if not 2 <= base <= 16 or not text:
        raise ValueError("invalid base/input")
    total = 0
    for char in text.upper():
        digit = DIGITS.find(char)
        if digit < 0 or digit >= base:
            raise ValueError("digit outside base")
        total = total * base + digit
    return total

FUNCTION BinarySearch(A, key)
  low ← 0
  high ← LENGTH(A) - 1
  WHILE low <= high
    mid ← (low + high) DIV 2
    IF A[mid] = key THEN RETURN mid
    IF A[mid] < key
      THEN low ← mid + 1
      ELSE high ← mid - 1
    ENDIF
  ENDWHILE
  RETURN -1
ENDFUNCTION

def search(root, value):
    current = root
    while current is not None:
        if value == current.value: return True
        current = (current.left if value < current.value
                   else current.right)
    return False

def inorder(node):
    if node is not None:
        inorder(node.left)
        visit(node)          # L, Root, R
        inorder(node.right)
